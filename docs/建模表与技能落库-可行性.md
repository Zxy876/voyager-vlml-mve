# 「maieutic 摆环境位」对不对：取决于建模表是哪一层

> 你的判据：**先看 VLML 建模表能不能由 maieutic 产出落进 db；能，环境位就成立；不能，就不成立。**
> 这条判据是对的。查完代码的结论是：**建模表分三层，只有中间那层能"学"出来。**
> 而"能学"的那层，现在已经在学了 —— 只是存在 JSON 里，且**一个字段塞了两种语言**。

## 结论（三句）

1. **语义层（列是什么意思、什么算首血）产不出来**。它来自 4 份**手写**文档
   （`vlml_schema.py:445-450`：`DATA_MODEL.md` / `DERIVED_TABLES.md` /
   `column_definitions.yaml` / `DATA_DICTIONARY.json`）。maieutic 没有"业务口径"的来源，
   让它写就是编造。→ **环境位在语义层不成立。**
2. **查询层（这题用了哪张表、哪些列、怎么过滤、跑通的那条 SQL）能学，而且现在就在学**
   —— 只是落在 `skill_store.json` 而不是 db，而且**没有把"用了哪些表"结构化存下来**。
   → **环境位在查询层成立。**
3. **判据对齐不用改**：`examine` 判 `open` 为空 → `task_critic` 返回 `success` →
   `learn_milestone_skills` 这条**唯一出口**已经在（`learn_orchestrate.py:811-812` → `:210`）。
   把"写 JSON"换成"写 db"，门槛一个字都不用动。

## 一、"VLML 建模表"到底是什么（取证）

`vlml_schema.model_specs()`（`:643-734`）把 4 份手写文档解析成 21 张表的结构化声明：

```
{tables: {name: {title, purpose, grain, pk, parent, keys, upstream,
                 column_desc, metrics, key_columns, example_sql, layer}},
 fingerprint, files}
```

另有 `discover()`（`:737-746`）从 **VLML 源码**（`tools/sql/*.sql` + 函数调用图）抽出
`lineage / insights / tools / section_insights`。

**两条都是静态抽取，不是学习。** 一条读人写的 md，一条读源码。maieutic 在这两条路之外没有第三条。

### 三层拆开看，才知道哪层能学

| 层 | 内容 | 可自动获得？ | 谁产 |
|---|---|---|---|
| **G1 结构** | 表/列/类型/PK/基数 | ✅ `information_schema` + 抽样（`scene_db.schema_block()` 已实现） | 可自动 |
| **G2 血缘** | 谁由谁算出（`base_events → agg_*`） | 🟡 静态可抽（`discover_lineage` 读 SQL 文件）；从"同题同用两表且 join 能跑"只能弱反推 | 文档/源码 |
| **G3 口径** | `fb_team_won` 是什么意思、什么算"首血" | ❌ **不能** | **人**（或抄官方文档，那是抄不是学） |

**所以"maieutic 产出建模表"要看你指的是哪层**：G1 它做得到（而且不需要 maieutic，`schema_block` 就够）；
G3 它做不到 —— 它的全部输入是"问题和材料"，材料里没有"这列什么意思"就只能猜。

**这决定了环境位的边界：maieutic 是 G3 的读者，不是作者。**

## 二、查询层已经在学，但存错了地方（现存不一致，取证）

`skill_store` 的 `code` 字段被**两个写入端塞了两种语言**，**两个读取端各假定一种**：

| 写入端 | 写什么 | 位置 |
|---|---|---|
| `_absorb`（消费侧沉淀） | **纯 SQL** | `consume.py:1789` `code=sql` |
| `learn_milestone_skills`（学习侧） | **Python 脚本**（`RESULT=…`） | `learn_orchestrate.py:264` `code=code` |

| 读取端 | 当成什么 | 位置 |
|---|---|---|
| `_refill_sql`（回填） | 当 SQL，直接贴进"配方 SQL"段 | `consume.py:239` `SQL：\n{code}` |
| `_make_skill_fn`（执行域） | 当 Python，`exec()` 它 | `local_agent.py:335` → `:344` |

**没有 `kind` 判别。** 于是：场景 A 消费侧沉出来的纯 SQL，到了学习侧会被当 Python 重放（必炸）；
学习侧存的脚本，到了消费侧会被当"SQL 配方"喂进 prompt（喂错）。

这不是风格问题，是**一个字段放两种语言**的必然结果，也只有 db 的显式列能治。
**这条就是"该落 db"最硬的理由——比"可查询"更硬。**

## 四、落 db 的三张表（技能名 = 它回答的那个问题）

```sql
-- ① 问题 = 技能的名字（你说的"名字在这里是关联的问题"）
problem(problem_id PK, scene, question, topic_id, dim_id, import_id, created_at)
-- ② 查询层建模：这题用到哪些表/列（**能学的那层**）
plan_ref(plan_id PK, problem_id, table_name, column_name, role, note)
-- ③ 配方：验证过的 SQL / 脚本
recipe(recipe_id PK, problem_id, kind, sql, py,
       depends_on, verified_rows, verified_by, verified_at, superseded_by)
```

三列是关键，缺一不可：

| 列 | 为什么 |
|---|---|
| `kind`（`sql` / `py`） | 治 §二 那个"一字段两语言"——`_refill_sql` 只取 `kind='sql'`，`_make_skill_fn` 只包 `kind='py'` |
| `depends_on` | 配方引用配方。原版是函数调函数（trial1 的 51 条里 7 处），db 里就是一条自引用 —— **组合不会丢**，只是从"调用"变成"关系" |
| `superseded_by` | 旧账不删、指向新版 → **顺手解掉上一轮"旧账被覆盖"的缺口**，而且是 db 天生的能力，不用另造冻结机制 |

消费侧一条 JOIN 取技能，而且**可解释**：

```sql
-- 按表找技能：哪些配方用过 agg_first_blood_stats
SELECT p.question, r.sql, r.verified_rows
FROM plan_ref pr JOIN problem p USING(problem_id) JOIN recipe r USING(problem_id)
WHERE pr.table_name = 'agg_first_blood_stats' AND r.superseded_by IS NULL;
```

比向量相似度强的地方：**命中理由可读**（同表同列 → 命中）、**可审计**（用了几次、验证过几行）、
**可去重**（同表同列同口径 → 并成一条，而不是像现在 `skill_store` 那样堆 22 条同题技能）。

## 六、三条风险（要写进验收，别事后补）

1. **SQL 编排只覆盖数据型。** 知识型/本机场景的配方是"多步 Python + 联网"，编不成 SQL。
   db 里 `kind='py'` 的行只存执行指针，跑还是走 `run_saved`。**别一刀切成 SQL。**
2. **跑通 ≠ 口径对。** `rows>0` 只证明能取到数，不证明取的是对的量
   （`_REFILL_SYSTEM` 规则 0 就是为这个写的：「问崩盘率，配方是 K/D，照样填进去」）。
   所以 `recipe` 必须有 `verified_by`（谁判的、判了几条维度），且**可被 superseded**，不能一次写死。
3. **G3 不许反推。** `plan_ref.note` 只许写"我用了它、用它算这个量"，**不许写"它是什么"**
   —— 那是 `vlml_schema` 的地盘。两处都写就是两本账打架，而且错的那本没人校。

## 七、回答"环境位置对不对"

| 你的前提 | 检验 | 环境位 |
|---|---|---|
| maieutic 能产出**语义**建模表 | ❌ 要 G3 口径，来源只有人写的 4 份文档 | **不成立** |
| maieutic 能产出**查询**建模（表/列/过滤/验证过的 SQL） | ✅ 能，且已在学，只是没落 db | **成立** |
| spec 闭合 = 任务成功 = 允许落库 | ✅ 已经是（唯一出口 `learn_milestone_skills`） | 成立 |

**所以：环境位成立，但 maieutic 在 G3 只是读者。** 把它写成作者，它会开始编造口径 ——
这比"追问退化成判分"更贵：判分错了当轮就知道，口径错了会污染之后几百条配方。
