## 二、可见边界规则（一条，可检查）

### 2.1 规则原文

> **分类标签是教师面语言；学生面只允许"下一问"。**
>
> 具体：`drift / revision / bug / category / category_hint / bias` 这些**分类名**，
> 永远不出现在 Voyager 能读到的任何文本里；Voyager 只读得到**追问句本身**（`questions`）
> 和**预防式的"别这么答"**（`pattern`）。
> 判定结果（"它是 drift"）只写进账本，不进 prompt。

四条推论：

1. `critique` 字段（唯一回灌通道）里只能有 `questions` 的原文，**不能**有分类名或"你偏离了"这类判定语。
2. `avoid`（预防清单）允许放 `pattern` 文本，**必须已剥掉 `category`**，且措辞是"别这么答"而不是"你犯了"。
3. `hint_depth`（first/deeper/scaffold/micro）**不是**分类名，它是"提示给到多细"——允许出现，但只能以**实际展开后的提示文本**出现，不许把 `scaffoldHint` 这个枚举名印给学生。
4. 维度渲染只给 `question`，**不给 `why`**（`why` 是内部理由，写明"别复述给助手"）。

### 2.2 字段级白名单

| 字段 | 产出位置 | 学生面（prompt / RESULT 回显 / learnBar） | 教师面（账本 / 面板 / 导出） |
|---|---|---|---|
| `dimensions[].question` | `maieutic_scaffold.py:187` | ✅ 原样 | ✅ |
| `dimensions[].why` | 同上 | ❌ **禁** | ✅ |
| `expected_drifts[].pattern` | `:91` | ✅ 必须以"别这么答"形态（`drift_notes()` 已做） | ✅ |
| `expected_drifts[].category` | `:91` | ❌ **禁** | ✅ `ckpt_maieutic/*.json` |
| `gaps_still_open` → `questions` | `maieutic_gate.py:172` | ✅ 只 `questions` | ✅ 全量（含 `open[]` id） |
| `gaps_addressed` / `open`（id 列表） | `:171` | ❌ 禁（id 列表 = 判分结果） | ✅ `critic_gate` |
| `emergent_gaps` | `:173-174` | ❌ 禁（是"清单外发现"） | ✅ |
| `passed` / `complete` | `:171` | ❌ **禁**（判分结果） | ✅ |
| `intent_diff.category` / `category_hint` / `bias` | 未实现 | ❌ **禁**（v3 曾想给学生 `category_hint`，**此条作废**） | ✅ |
| `hint_depth` 枚举名 | `maieutic_diagnose`（未实现） | ❌（只给展开后的提示文本） | ✅ |

### 2.3 三处卡口 + 可跑断言

规则要可检查，必须钉在"文本离开教师面"的三道门上，而不是靠代码评审自觉：

| 门 | 位置 | 卡什么 | 违反时 |
|---|---|---|---|
| 门 1 | `local_agent.solve()` 拼 user 之前（`:543-560` 附近） | `critique` / `avoid` / `dimensions[].question` 里不得含分类词 | 过滤掉该词所在分句并记 `reuse_errors`（不静默） |
| 门 2 | `task_critic.py:160` 返回前 | `critique` 只由 `questions` 拼成 | 断言 `set(critique.split()) & _TAGS == ∅` |
| 门 3 | `panel_data.skill_detail`（`:755-778`） | 面板卡片可显示分类（教师面），但**导出给学生的文件**（`export_md`）不得带 | `export_md.py:323` 分支加白名单 |

**断言（MVP-1 第 7 项，`mve/test_visibility_boundary.py`）**：

```python
_TAGS = {"drift", "revision", "bug", "category", "category_hint", "bias", "passed"}

def test_gate_questions_carry_no_category():
    # 闸门返回的 questions 原样进 critique，不得夹带分类词
    g = {"questions": ["首血事件取的是哪张表？", "队伍名从哪儿 join？"],
         "open": ["d1"], "addressed": [], "passed": False}
    crit = " ".join(g["questions"])
    assert not (_TAGS & set(crit.lower().split()))

def test_drift_notes_strip_category():
    # 预防清单只出 pattern；pattern 里若含分类词必须被剥
    sc = {"expected_drifts": [{"category": "drift", "pattern": "只查了 games，没查 ext_*"}]}
    out = maieutic_scaffold.drift_notes(sc)
    assert out == ["只查了 games，没查 ext_*"]          # 无 "drift"

def test_dimension_why_never_rendered():
    # 维度渲染只给 question
    rows = [f"{str(d.get('question'))}" for d in [{"id":"d1","question":"…","why":"内部理由XYZ"}]]
    assert "内部理由XYZ" not in "\n".join(rows)
```

**当前状态**：门 1/门 3 未接线，门 2 天然成立（`task_critic.py:160` 只拼 `questions`）；
`drift_notes()` 已剥 `category`（`maieutic_scaffold.py:271-283`）——**它是这条规则的合法先例，
新代码照它写就行，不用另发明一套。**

> 顺带回答"会不会跟着 critique 一起进 `render_human_message`"：**现在不会，因为分类根本不存在。**
> 但这不是"设计上不会"，是"还没造出来"——所以上面三道门必须在 `intent_diff` 落地**之前**接好，
> 否则它一出生就会顺着 `critique` 漏进学生面，追问立刻退化成判分。

## 三、「当时怎么答、被追问什么、怎么解释的」记在哪

### 3.1 现状：三本账，各自都有覆盖点

| 账本 | 文件 | 字段 | 记什么 | 覆盖行为 |
|---|---|---|---|---|
| A · 跑通账 | `ckpt_maieutic/<scene>/<qhash>.json` | `progress.codes[dim] = {question, code, answer, tools}` | 上次跑通的代码 + 答案 | **覆盖**：`:361` "本轮新跑的覆盖旧的" |
| B · 追问账 | 同文件 | `progress.iterations[dim] = {rounds, asked, gap, passed, tools}` | 上次被问了什么 | `rounds` **累加**，`asked/gap` **覆盖**（`:437-446`） |
| C · 技能账 | `skill_store.json` | `{text, code, blueprint, versions, history:[旧text], created, updated}` | 入库的配方 | `code`/`blueprint` **原地覆盖**（`:289-292`），`history` 只追加**旧 text**（`:279-281`） |
| D · 轨迹账 | `run_log.jsonl` | 固定白名单 25 个字段 | 这一轮学没学会 | **不含** `critic` / `gate` / `questions`（`_record() :1143-1205`） |

### 3.2 三个缺口（照实说）

1. **"怎么解释的"没有账。** MVE 没有 Phase 3；一次失败之后模型改的是**下一轮的 answer 本身**，
   没有"针对第 K 条偏离的回答"这个对象。A 账只留最后一次 `answer`，前面几轮的答案被覆盖。
2. **"被追问什么"只留最后一次。** B 账的 `asked` 是单值，不是数组；`rounds` 只知道问过几次，
   不知道每次问的是哪句。
3. **追问在进程内还活着，进程一退就没了。** `out["critic"]["gate"].questions` 只在
   `judge=True` 时写进内存 `_LAST`（`learn_orchestrate.py:1004-1008, 1017`），
   `_record()` 的白名单里**没有 `critic` 字段** → `run_log.jsonl` 里查不到。
   这是"白名单惯犯"的第六次（前五次：`reuse_errors` 等）。

### 3.3 补法（三处字段，不新建账本）

| # | 位置 | 改法 |
|---|---|---|
| 1 | `skill_store.add()` `:279-292` | `history` 元素从 `str`（旧 text）改成 `dict`：`{text, code, blueprint, updated}`。**向后兼容**：读到 `str` 元素按"只有 text 的旧格式"处理 |
| 2 | `learn_milestone_skills()` `:253-280` + `dim_codes`（`learn_orchestrate.py:824-828`） | `dim_codes` 每项补 `spec` / `answer` / `asked[]` / `covered[]` / `at`，写进技能条目新字段 `ledger` |
| 3 | `save_progress_codes()` `:361` + `save_progress_iterations()` `:437-446` | `codes` 保持"最新一份"（续学要用），**另存** `codes_history[]` 追加；`iterations.asked` 从 `str` 改成 `list[str]`（最近 5 次） |

不新建账的理由：**技能条目就是"那次 rollout 的档案"**（原版 `add_new_skill(info)` 存的也只有
`program_code` + 描述）。把 answer/追问挂到同一条目上，才是"同一次学习的四个面"，分开放就又变成两本账打架。

### 3.4 面板怎么让评审一眼看出旧账没被改写

三件，全部复用现有 `skill_detail`，**不新开页面、不加按钮**：

| 显示 | 数据来源 | 判读方式 |
|---|---|---|
| **版本号** `v3` | `skill_detail.versions`（已有，`panel_data.py:773`） | 涨了 = 被重做过 |
| **冻结时间戳** `旧账冻结于 10-23 21:40` | 新增 `skill_detail.frozen_at` = `history[-1].updated` | 这个时间戳**不该变**（它是"上一次"的落盘时间，不是本次） |
| **新旧并排**（点开 chip 展开） | `skill_detail.prev = {text, code, updated}` = `history[-1]` | 左边旧 `code`、右边当前 `code`；旧 `answer` 在下 |

现有 chip 改一行就够（`dashboard.py:1381`）：

```js
${x.versions>1?`<span class="chip warn" data-k="${x.key}"
   title="旧账冻结于 ${x.frozen_at||'—'}">已覆盖 ${x.versions} 版</span>`:''}
```

点开走已有的技能详情抽屉（`skill_store` 的 key 直查），渲染 `prev` vs 当前 —— 左右两栏。

### 3.5 验收断言（重做一次就能跑）

```
1) 记下第一次入库后 skill_store.json 里该条目的 code、created、versions(应为 1)
2) 同一道题再学一遍（同一维度 id）
3) 断言：
   · history[-1].code == 第一次的 code（逐字节）
   · created 未变
   · versions == 2，updated 变大
   · ledger.asked 里能看到第一轮被问的那句
4) 面板：卡片出现「已覆盖 2 版」+ 旧账冻结时间戳 = 第一次的 updated
```

**现在跑这条会失败在第 3 步第 1 条**（`history` 里只有 text，没有 code）——这就是 1.2 表里第 4 行标
"裁剪（承载点不全）"的证据。

## 四、给评审的三分钟走法

| 步 | 动作 | 预期 | 失败长什么样 |
|---|---|---|---|
| 1 | 知识型问题 → 「交给 Voyager 回答」 | `learnBar` 动起来；日志出现「维度：N 条」 | 直接 `0 维度` = 备课段坏了 |
| 2 | 等第一条维度判失败 | 日志出现 `追问历史：… 上次问过：…`；第二次 exec 的 prompt 含该句 | 第二次 prompt 与第一次一字不差 = 回灌断了 |
| 3 | 看失败轮次的技能库 | **不涨** | 涨了 = 真空成功（硬闸坏了） |
| 4 | 让一条维度闭合 | 技能库 +1；图谱节点闭合；导入反查 +1 | 技能 +1 但图谱没动 = 收尾段半截 |
| 5 | 重做同一题 | 卡片「已覆盖 2 版」；旧账内容不变 | 只涨版本号、点开没有旧内容 = 3.4 还没做（**预期内的裁剪**） |

第 5 步的"点开没有旧内容"是**本期已知缺口**，不要记成新缺陷——它对应 §3.3 表格的 1 号改动。
