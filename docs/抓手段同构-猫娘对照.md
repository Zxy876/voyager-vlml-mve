### 2. 开关的语义（关键，不只是"能开能关"）

猫娘把「能不能用」拆成**三种状态 + 一句前置依赖**，不是布尔值：

| 文案 key | 中文原文 | 含义 |
|---|---|---|
| `masterRequired` | **请先开启猫爪总开关** | 顶层总开关关着 → **下面所有条目一律不可用**（级联门控） |
| `serverOffline` | 猫爪服务器未启动 | 依赖的服务不在（`127.0.0.1:8088`）→ 如实说"没启动"，不是"功能没做" |
| `capabilityNotReady` | {{name}}尚未就绪，点击尝试启用 | 能力在但没就绪 → 给人一个补救动作 |
| `checking` | 查询中... | 状态未探明前**先禁用**，不假装可用 |

（`static/locales/zh-CN.json:2886-2898`；`common-ui-hud.js:330-333` 的注释也写了
「Agent 能力开关默认禁用，title 显示查询中；只有状态机检测到可用性后才逐个恢复交互」。）

### 3. 插件自己的两个开关字段

| 字段 | 取值 | 含义 |
|---|---|---|
| `[plugin_runtime] enabled` | true/false | 这个插件启用没有（关掉 = 它的条目不该进模型工具表） |
| `[plugin_runtime] auto_start` | true/false | 随宿主启动否 |
| `[plugin.ui.guide] permissions` | `["state:read", …]` | 插件声明自己要的权限（面板页也按这个门控） |

取证：`plugin/plugins/mcp_adapter/plugin.toml:35-40`（`permissions = ["state:read"]`）、
`:42-45`（`[plugin_runtime] enabled = true / auto_start = false`）；
`plugins/catgirl_daily_planner/plugin.toml:21-23` 同字段。

| 写接口 | `POST /api/actions/switch {scene, group, enabled}`；`group="*"` = 总开关 | `mve/dashboard.py`（do_POST 分支） |

### 与 neko 的差异（诚实列出）

| 项 | neko | MVE 现状 | 影响 |
|---|---|---|---|
| 权限粒度 | `permissions = ["state:read"]` 这类**声明式权限**，面板按权限门控 | **没有权限位**；只有「组开关 + 总开关」 | 现在的隔离靠"关组"，不是"这个插件只能读不能写"。MVE 的本机原语本来就只读（`list_files/read_file/read_json/query_sql`），所以现在够用；要接远端 MCP 写操作时**必须先补权限位** |
| 可用性探测 | 状态机（checking → ready / unavailable），探后端服务与端口 | 只按"条目在不在 + 开关开不开"判；数据源缺失由 `scene_profile` 单独判 `missing` | 没有"就绪探测"这一档；面板不会显示"猫爪服务器未启动"式的依赖告警 |
| 自动启动 | `auto_start` | 无（场景一注册即可用，没有 start/stop 生命周期） | 对 MVE 无害：条目是纯函数/重放，不需要常驻进程 |
| 条目级开关 | 每个条目一个 slider（键鼠、浏览器…） | **组级**开关（组内条目一起开/关） | 用户要"只关 read_file 留 list_files"时做不到；`ActionSpec` 上再加一个 per-entry 开关即可（`group` 之上再加一层 `enabled`），先按组做是因为组=能力来源，语义更稳 |

## 三、怎么用（给普通用户 / 给演示）

1. **普通用户下载下来，跑在本机**：默认场景 A 是 VLML 数据域；新建的场景默认**数据源就是本机**
   （应用工作区 + 场景目录），不需要配库（判定见 `mve/scene_profile.py:63`）。
2. 场景栏下面那排就是**猫爪总开关**：总开关关掉 → 下面所有组变 🔒 并提示
   「请先开启猫爪总开关」；单独关一组 → 该组条目对模型不可见、调用被拒，**拨回来即恢复**
   （不删条目、不重新学）。
3. 演示脚本（服务器）：
   ```bash
   POST /api/actions/switch {"scene":"B","group":"*","enabled":false}   # 总开关关
   POST /api/actions/switch {"scene":"B","group":"本机能力","enabled":true}
   POST /api/actions/switch {"scene":"B","group":"*","enabled":true}    # 拨回
   ```
   关掉期间导入一句话：`consume` 拿不到任何本机原语 → 如实说「本机工作区里没有能回答它的数据」，
   **不会**退回 VLML/rib 去凑一个答案。

## 四、待办（按优先级，不是这次做）

1. **权限位**：`ActionSpec.permissions: list[str]`（`read:file` / `read:sql` / `net` / `write`…），
   `invoke()` 先查权限；本机原语一律 `read:*`。接远端 MCP 写操作前必须做。
2. **就绪探测**：`group_state()` 增加 `checking` / `unavailable(why)`，探测项 = 数据源可读、
   MCP server 连通（`mcp_gateway.connect_all` 已有结果可复用）。
3. **条目级开关**：`ActionSpec.enabled`，与组开关串行（条目开 ⇔ 总开关 ∧ 组开关 ∧ 条目开关）。
4. **插件生命周期**：`auto_start` 对应 MVE 里根本没有的东西 —— 先不照抄，除非要做常驻工具。
