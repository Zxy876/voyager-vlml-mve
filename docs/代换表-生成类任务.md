# 代换表：把生成类任务压成一句话判定

> 2026-11-03 拍板方向：**不接更多工具**。把目标分而治之，把 R（交付）从"产物"缩到"一句话结论"，
> 再做等价代换。这样生成类用户（代码 / 前端 UI / AIGC 图 / 视频）也能把需求输进对话页，
> 而不需要 MVE 具备预览能力。

---

## 一、为什么能代换：烧 token 的不是渲染

一个生成任务卡住，token 烧在三个地方：

| 烧在哪 | 例子 | 能不能文字化 |
|---|---|---|
| **决策** | 选哪个方案、根因是哪个、参数取多少、要放弃什么 | **能**，而且是句号式的 |
| **试错** | 改了 7 版、装了 3 遍环境、生了 40 张图 | 能，但它只是决策错误的后果 |
| **渲染** | 像素、帧、字体落位 | 不能，也**不该**由 MVE 承担 |

关键点：**花掉预算的是决策，不是渲染。** 渲染很便宜，重渲染很贵——贵在每次重来都要重跑一遍决策。
所以把决策抽出来单独解决，产物留给 agent 渲染，等价性成立。

代换后的等式：

```
生成任务 = 决策集 D × 渲染 f
MVE 交付 D 的取值；agent 执行 f(D)
```

MVE 不再交付 `f(D)`，只交付 `D`。**产物由 agent 生成，因此 MVE 不需要预览。**

---

## 二、代换的三条判据（三条全过才代换）

把需求写成一句话之前，先自检：

1. **产物可抽离**——把产物拿掉后，剩下的问题还成立吗？
   （"帮我做个落地页"→ 不成立，这是执行委托；"这个落地页在 768px 下栅格该取几列"→ 成立）
2. **答案能一句话说完，且不含"看情况"**——出现"看情况"就说明还没抽到决策层，只是把任务换了个说法。
3. **带回 agent 无需解释就能执行**——参数要能直接填进去。若需要人再翻译一遍，这条没通过交付性检验。

三条有一条不过：**不代换，如实拒绝**。这是"未学/不编数"应该触发的地方。

## 三、四类任务的代换实例

### 代码

| | |
|---|---|
| 卡住的样子 | 改了三版还是同一个报错；装依赖装到环境崩 |
| 抽出的决策点 | 根因归属、版本约束、必须放弃的特性 |
| 一句话问法 | 在 `<框架+版本>` 下，`<报错原文>` 的根因是哪一个？ |
| 一句话答案（形态） | `根因 = X；触发条件 = Y；代价 = 放弃 Z` |
| 带回 agent | 直接改对应位置，不需要再解释 |

### 前端 UI

| | |
|---|---|
| 卡住的样子 | 间距怎么调都不对；响应式在某个断点崩 |
| 抽出的决策点 | 栅格数、间距阶梯、断点位置、容器上限 |
| 一句话问法 | `<组件>` 在 `<宽度区间>` 下，栅格 / 间距 / 断点取什么值？ |
| 一句话答案（形态） | `12 列 / gap 24 / 断点 768·1024 / 内容宽 1200` |
| 带回 agent | 直接写进 CSS 变量，不需要看图 |

### AIGC 画图

| | |
|---|---|
| 卡住的样子 | 生了 40 张都不像；同一 prompt 结果漂移 |
| 抽出的决策点 | prompt 结构、必需词、必排词、权重区间、采样参数 |
| 一句话问法 | 要得到 `<视觉特征>`，prompt 里必须出现 / 必须排除哪些词？ |
| 一句话答案（形态） | `必含：材质+光位+镜头；必排：plastic, oversaturated；权重 <0.6 无效` |
| 带回 agent | 直接改 prompt，重生成一次 |

### 视频

| | |
|---|---|
| 卡住的样子 | 运镜一长就崩；首尾帧接不上 |
| 抽出的决策点 | 生成路径（文生 / 首尾帧）、单段时长上限、转场策略 |
| 一句话问法 | `<镜头意图>` 在 `<时长>` 下用哪条路径更稳？上限是多少？ |
| 一句话答案（形态） | `用首帧+末帧；单段 ≤3s；连续运镜前插 1.5s 静止` |
| 带回 agent | 直接改分镜参数 |

**四个例子的共同结构**：答案是**参数、根因或判据**，没有一个字是产物。
这就是"等价"的严格含义——MVE 交付 `D`，agent 交付 `f(D)`。

## 四、分而治之：一个任务拆成 N 个决策点

一个生成任务通常不止一个决策点。逐个代换、逐个判定，串起来就是配方：

```
"帮我做个能用的落地页"
  ├─ 断点取哪几个？        → 768 / 1024 / 1440
  ├─ 栅格与间距阶梯？      → 12 列，8 的倍数
  ├─ 首屏必须包含什么？    → 价值主张 + 单一 CTA
  └─ 什么必须放弃？        → 首屏不放轮播、不做视差
```

四句都有结论 = 四个维度闭合 = 配方完整。**这正是 MVE 已有的机制**：

| MVE 现有机制 | 换题面后 |
|---|---|
| `maieutic` 拆维度 | 拆决策点（不再是取数维度） |
| 逐维度闭合判定 | 每个决策点是否有明确取值 |
| 全维度闭合 → 结晶组合技能 | 决策集完整 → 一条可搬的配方 |
| `mastery` 1/30 计量 | 每答对一个决策点算一分 |

**不需要新机制，只需要换题面。** 这是最省的路径，也正好符合"不接更多工具"。

## 五、不可代换的三类（必须如实拒绝）

代换不是万能的。以下情况问不出答案，因为答案不在文字里：

1. **执行层能力不足**——模型就是画不出那个手、渲染引擎就是不支持那个效果。这不是决策问题，学一百遍也没用。
2. **审美判定**——"够不够好看"没有客观判据，一句话答案给不出。只能人看。
3. **私有上下文缺失**——答案依赖你项目里的东西（内部组件库、品牌规范），MVE 看不到，也不能编。

这三类应当触发"未学 / 不编数"，而不是硬凑一句话。**承认边界比扩大覆盖更能建立可信度。**

---

## 六、代价：回合变慢，换来可搬运

放弃预览不是免费的，代价要写清楚：

| 得到 | 付出 |
|---|---|
| MVE 不必实现渲染、不必接工具、不必同构工具面 | 判定延后——只能在 agent 渲染后才知道参数对不对 |
| 配方是纯文本 → **跨 agent 无损搬运** | 交互回合从"对话内闭环"变成"跨工具闭环" |

第二行是这次收敛最大的结构性收益。之前台账 #12/#13 留的残留风险是：
**技能带 `sql` + 工具名单，跨工具面迁移会撞在调用层。** 一旦 R 缩到参数/判据，配方里不再绑工具名，
只剩取值和条件——**这个风险自动消失了**。缩小范围不是为了省事，是为了可搬运。

---

## 七、回灌：MVE 唯一的验证来源

MVE 自己判不了参数对不对——那要渲染。所以闭环必须靠人回报：

```
MVE 给参数 → agent 渲染 → 人看结果 → 回报"跑通 / 没跑通"
```

回灌只需要两个值：

- **跑通** → 这条配方 `mastery` 涨，进入可复用集
- **没跑通** → 记 `reuse_errors`，写明卡在哪一步（是参数错，还是执行层能力不足）

这也解释了为什么 `coach.explain` 不接闸是自洽的：**人在环中**，判定由人做，MVE 只负责存配方和记账。
但代价也要认：**回灌一断，MVE 就不知道自己给的参数对不对**，配方会慢慢退化成"看起来很有道理的话"。
所以回灌不是可选项，它是这套东西能被称为"仪器"的前提。

---

## 八、对产品的三条约束

1. **入口只做"代换"，不做"执行"。** 生成类用户进来时，第一件事是把他的任务翻译成一个可判定问句，而不是接他的活。翻译不出来的，直接说"这类我做不了，原因是你缺的是执行不是决策"。
2. **答案必须是参数形态。** 输出里如果出现"你可以试试……""建议考虑……"，说明没落到决策层，是废答案——这种话术对 agent 零价值。
3. **不接工具。** 每接一个工具，就多一份工具面不同构的债务，而且会立刻把 MVE 拉进 agent 的赛道——那条赛道永远追不上 WorkBuddy。

## 九、更直接的一条路：R 不用声明，跑一遍就量出来了

上面八节讲的是"人先把需求代换成一句话"。但还有一条更省事的路，**不需要用户懂代换规则**：

> 人原样输入需求 → 学习跑一遍 → N 条维度里只有 1-2 条闭合 → **那几条就是这个任务在 MVE 下换算出来的 R**。

代码已经具备这个能力。`maieutic_gate.check()`（`maieutic_gate.py:188-233`）返回四个字段：

| 字段 | 含义 | 现在的用法 |
|---|---|---|
| `addressed` | 已答到的维度 id | 计入闭合 |
| `open` | 仍未闭合的维度 id | **当作要补的缺口** |
| `questions` | 针对 open 的追问 | 下一轮接着问 |
| `emergent` | 闭合后新冒出的缺口 | 下一轮的生长点 |

`passed` 严格要求 `open` 为空，所以"N 条里闭合几条"是**现成可读的数**。

### 语义要翻一下：open 不全是缺口

这是这次收敛最关键的一处改动——**不是改代码，是改语义**。

现在 `open` 一律被当成"缺口"，于是系统会一直追问、重试、再拆，试图全部闭合。
但如果那条维度本来就没有材料（要执行层、要审美、要私有上下文），**追问到死也不会闭合**，只是白烧 token。

所以 `open` 要拆成两类：

- **可补缺口**：材料在，只是这次没答到 → 下一轮追问（对应图中的橙色）
- **边界**：材料缺，或连续两轮仍 open → 划出去，归 agent（对应灰色）

判定方法不需要新机制：看该维度的材料支撑（`source_binding.check` 的证据），
或看它是否跨轮稳定 open。跨两轮不动且无材料 = 边界，等价于已有的 `unreachable` 语义。

### 于是每次学习结束，该输出两份清单

```
R（可交付）        2 条  ← 沉淀技能，可搬运
边界（归 agent）    3 条  ← 附原因：执行层 / 审美 / 私有上下文 / 材料缺失
```

**未闭合的维度不该被丢掉**——它们是最有价值的产出之一。用户看到这 3 条，就知道"这部分别在 MVE 里耗"。
现在的实现会把它们留在 `pending_dimensions.json`（`routing.py:23-27`，`status=pending_review`），
但那是给系统内部用的审计区，**没有以"边界清单"的形态呈现给用户**。这是产品缺口，不是机制缺口。

### 闭合率是 R 的宽度，但必须配一个纯度

`闭合率 = addressed / dimensions` 直接就是"这个任务有多少落在 MVE 能力范围内"。
它比任何自述都可信，因为它是跑出来的。

但它单独看会骗人。**场景 J 就是活证：4 条技能全部闭合，4/4，但内容全错**——闭合的是联网缓存的错误实体。

所以必须并排报两个数：

| 指标 | 算法 | 它回答什么 |
|---|---|---|
| **闭合率** | `addressed / dimensions` | R 有多宽 |
| **闭合纯度** | 闭合维度里 `provenance` 正确且过引文/字面量守卫的比例 | R 有多真 |

只盯闭合率，系统会被优化成"更容易闭合"，而不是"更正确"——那是刷分，不是学习。
11-03 加的 `provenance` + 引文字面守卫，正好是纯度的分母。

### "追着闭合的问"有两种含义，都对

1. **对人**：只在那 1-2 条上追问、加深、验证，别在边界上耗。这是省 token 的直接做法。
2. **对系统**：以闭合的为种子往外扩（Voyager 的 automatic curriculum）。种子就是 `addressed`，
   方向就是 `emergent`——**闭合之后新冒出来的缺口，才是真正值得问的下一问**，
   因为它在已有材料的紧邻处，那里有料可挖；而长期 open 的，多半是边界。

这两件事合起来是一个正向循环：闭合 → 沉淀 → 长出 emergent → 再闭合。
**R 就这样一圈一圈变宽，而且每一圈都有实证。**

---

> 一句话：**agent 交付产物，MVE 交付让产物一次做对的那个数。**
> 再补一句：**这个数不需要谁来声明范围——跑一遍，闭合的那几条就是范围。**
