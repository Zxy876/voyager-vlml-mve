摘要（一页看懂）

Voyager-VLML-MVE 把「Voyager」的在线学习方法从游戏世界搬到了真实数据库世界：系 统像一名学生一样刷题——从课程出题、动手查库取证、被判卷、到把做对的题沉淀成可复用的「技能」； 当人真正提问时，系统检索这些技能编排作答，并按复用情况记账「掌握度」。

三个核心能力：① 双线架构（学习线刷题积累、消费线复用作答，共享同一份技能库）； ② 防幻觉三闸（进技能库的东西必须真实取到数、字面量可指认、且不会无限膨胀）； ③ 1→n 可插拔场景（新接一个数据库领域，不改一行代码）。

本文是导读版：用最少的前提知识讲清系统是什么、怎么工作、凭什么可信、边界在哪。 所有技术细节（含代码行号级对照）见完整版白皮书。

序言

大语言模型很擅长「说」怎么做一件事，但不擅长证明自己真的做到过。问它一个数据库问题， 它可能给出一段看起来正确的 SQL——也可能凭空编出一个根本不存在的表名。原版 Voyager 在游戏 Minecraft 里给出了一种回答：让模型像学生一样反复练习、被批改、把成功的做法存成技能， 越学越强。

本系统要回答的问题是：这套「越用越强」的范式，能否在真实数据的世界里成立？真实世界 没有游戏那样的即时得分，取数会失败、查询会串库、模型会幻觉——所以它比游戏难，也因此更有价值： 它建立了一套「每一条被记住的知识，都附带着当时的真实证据」的纪律。

这份白皮书面向所有想了解本系统的读者——不要求读过 Voyager 论文，也不要求读过源码。

一、项目概述

读完本章你应当能回答：这个系统是什么、和「直接问大模型」差在哪。

1.1 它是什么

Voyager-VLML-MVE 是一个在线强化学习系统：它不重新训练模型，而是让模型在「做题—批 改—沉淀」的循环里积累一份外挂的技能库。模型还是那个模型，但它身边多了一份自己写过、 被验证过的解题配方集，以及一张记录「数据世界里什么值从哪张表来」的知识图谱。

1.2 它解决什么问题

直接问大模型用本系统
答案无从核实，可能幻觉出表名、列名、数值答案必须来自真实取到的数，字面量逐个可指认
每次都从零开始，问一百次答一百次做对一次就沉淀为技能，下次直接复用
不知道「该值在哪张表哪个字段」时只能猜知识图谱记录指标语义与列来源，写查询前先看「教材」
用没用提示、答得对不对，没有账本掌握度按复用与求助情况逐笔记账

1.3 核心成果一览

能力一句话说明
双线架构学习线刷题积累，消费线复用作答，共享一份技能库
防幻觉三闸进库必真实、防膨胀、事实可溯源
知识图谱回答「这个值从哪来」的教材层，A/B 实测覆盖率 0%→100%
掌握度记账求助只给做法不给数值；用了提示打 0.85 折
1→n 可插拔场景新场景一条命令接入，不重启、不清库、不改代码
九分区面板学习曲线、技能库、因果时间线全链路可见

二、核心理念：三条设计原则

三条原则互为因果：双线决定「学到的给谁用」，图谱决定「凭什么写得对」，证据纪律决定「凭什么可信」。

2.1 双线架构：练习线和考试线分开

系统里有两条独立运转的线，共享同一份技能库与知识图谱：

学习线：出题 → 检索 → 动手执行 → 判卷 → 固化技能
判据：success 布尔 —— 真实取到数才算成功
消费线：人提问 → 检索技能 → 编排 → 叙述 → 裁判复核
判据：裁判独立复核的覆盖率 —— 作为交付尺度

关键纪律是：消费只编排复用，不现做合成。回答人的问题时，系统组合已验证的技能，而不临场 发明新做法——这保证了「考试考的都在练习范围内」，也让任何一条回答都能追溯到当初哪次练习验证过它。

2.2 知识图谱是「看不见的教材」

原版 Voyager 让模型写出能跑的游戏代码，靠的是把函数源码塞进提示词——模型看得见实现。 但数据世界里没有「源码」可看：模型知道该调查询工具，却不知道值在哪张表哪个字段。

本系统的答案是构建一张三层知识图谱（维度 → 工具 → 表），记录每个指标的语义、取数配方、各表 字段与典型错误——相当于给模型一本看不见的教材，写查询前先翻书。

证据：这不是理念，是带对照组的实验
同一道题（corrode_collapse）三种条件实测：无图谱 → 覆盖率 0%（连列都取错）； 图谱仅作提示 → 20% partial（骨架对但过滤位置错）；图谱 + 结构/参数硬断言 → 100%。 教训写在完整版里：提示打不过强先验，约束才行。

2.3 证据优先：没有真实取数，就没有发言权

系统的判卷不是「模型说对就对」。任何一次判对，背后必须有真实执行过的取数动作与观测结果； 任何一条进技能库的配方，都附带当时的真实观测。这条纪律贯穿第四章的「三闸」设计。

三、系统如何工作

用两次「旅程」讲清机制：一次学习，一次提问。

3.1 一次学习的旅程（六阶段闭环）

① 课程出题
→
② 技能检索
→
③ Rollout 执行
→
④ 判卷
→
⑤ 结晶
→
⑥ 里程碑

① 出题：课程规划器依据知识图谱的缺口出题——哪里没覆盖，就练哪里； ② 检索：从技能库召回相关配方作为参考（最多 5 条，见第四章防膨胀）； ③ 执行：模型生成查询并真实执行，逐条记录工具调用与返回观测； ④ 判卷：判据层裁决（详见 4.3），失败进「失败账本」并反馈给出题器； ⑤ 结晶：成功的做法连同真实观测被固化成技能； ⑥ 里程碑：多个技能组合成复合技能，标记能力台阶。

3.2 一次提问的旅程（消费线）

人提问
→
检索技能
→
多配方编排
→
叙述聚合
→
裁判复核
→
掌握度 +1

回答完成后由裁判独立取数复核（不是出题的那个角色自评），复核结果按掌握度规则记账 （第五章）。复用发生时，回答会明确标注「本答案复用了哪条技能、来自哪次学习」。

四、可信设计：防幻觉三闸与判据分层

本章回答一个问题：凭什么相信技能库里的东西是真的。

4.1 三道闸，各拦一类假

闸拦什么怎么拦
闸一：防膨胀技能库被低质配方刷屏，检索被垃圾淹没入库三分支（added / rewritten / skipped）；少于 12 字或与已有技能相似度 ≥0.90 直接丢弃；检索每次最多进 5 条
闸二：回灌闸技能描述与真实执行结果脱节判卷后的真实观测回灌进技能内容；解析失败有重试，不靠想象补全
闸三：事实溯源结论里的数值、表名是编的叙述中的字面量必须全部能在真实取数结果中指认，指认不出就不许说
一条重要的分工纪律
判错不写技能库——错误的做法不进库，因此不会通过复用链传播。三闸保护的对象是技能库 的纯净度：只要库是干净的，复用链上的一切（检索、编排、叙述）就建立在真证据上。

4.2 判据分层：LLM 判 + 确定性否决

判卷既不是纯 LLM 说了算，也不是死规则：

  • 确定性否决先行：全程没调过任何数据源 → 直接判负（「真空防线」）；执行层报错 → 直接判负，都不劳烦 LLM。
  • LLM 只在硬否决通过后裁决：判断做法是否真正回答了问题。
  • 判据层与掌握度层分离：判据层只产出 success 布尔；掌握度是另一本账（第五章），两层互不驱动。

五、掌握度与求助：像老师一样记账

掌握度不是分数，是「带半衰期的记忆账本」。

5.1 求助闭环：只给做法，不给数值

学生卡住时可以求助，但老师只讲思路、绝不报答案——给数值等于泄题。求助被记录在案： 本次答题用了提示。

5.2 记账规则

情形记账结果
答对，且没用提示记忆增强：半衰期拉长
答对，但用了提示 / 求助解释得分打 0.85 折，半衰期不动——不计全功，但也不惩罚
答错进失败账本，反哺课程出题
消费侧复用技能作答掌握度累计（例如首次复用记 1/30），重复导入同一问题可见增长

六、场景系统：1→n 可插拔

从一个游戏数据域，到任意数据库领域，扩展成本是一条命令。

6.1 场景是隔离的基本单位

每个场景有独立的技能库、知识图谱与数据工作区（scene_data/<id>/）。 非默认场景不继承默认库——这是用真实教训换来的契约：曾有场景问了「世界模型」， 却取到了另一个数据域的战队名。隔离不是配置建议，是系统强制。

6.2 四种场景类型

kind含义
vlml默认场景：Voyager 学 VLML 数据域（本系统的母题）
scene标准场景：绑定一个数据库数据源，独立学习
local本机场景：数据源就是这台电脑，符合普通用户直觉
missing配置失效：如实标注，不静默吞掉

6.3 插入新场景：不重启、不清库、不改代码

通过场景插入契约接入新数据域：既有场景与运行中的学习进程均不受影响。 实测记录见第八章。

七、人机分工模型

仿照云行业的「责任共担模型」：哪些由系统担保，哪些由人判断。

系统担保（架构强制）人负责（人在环中）
技能库无污染：判错不进库，进库必附真实观测提出有价值的问题、导入想验证的能力
消费侧回答可溯源：复用标注、裁判独立复核阅读叙述层内容并作业务判断
场景隔离：跨场景数据拿不到，而非「不该拿」为新场景准备数据源与图谱种子
能力边界如实标注（第九章），不虚报对预期差立项拍板：修产品，或改文档

这条分工解释了系统的一个设计取舍：面向人的叙事入口不做证据闸——因为它不写技能库、 不进复用链，人导入属于「补知识面」的教育路径，人在环中自行判断内容；多加一道闸就多一层限制。 系统把闸门全部投在「会被机器复用的东西」上。

8.3 可达性边界实测

系统会响亮地说「不」
向一个不含相关表的场景提问 → unreachable，在触达任何模型调用之前被可达性检查拒绝。 能力边界由架构强制，不靠提示词自觉。

九、能力边界与诚实声明

一份白皮书的可信度，取决于它说清楚了自己做不到什么。

边界含义
掌握度挂在题（topic_id）上是「带半衰期的记忆账本」，不是按能力项归档的评估体系
技能绑死出处的题，不迁移配方里写死了具体标识符，换个数据域要重学
消费判分是软尺子主尺子是「两边做法比对」（LLM 判），不是题库既有 rubric
图谱未消费 ext_* 表表节点仅从种子题 rubric SQL 派生
公开源缺 agg_* 派生层9 张派生表在公开源为 0 行，原料在 ext_* 表中
player_profile_report 在公开源必然失败其实现写死查询 0 行的派生表

上述边界与主线纪律一致：文档声明和产品能力保持一致。发现预期差时，或修产品、或改文档， 两条路都要经过评审拍板。

十、术语表与深入阅读

10.1 术语表

技能（Skill / 配方）
一次被验证成功的做法，存成可检索、可复用的条目，附带当时的真实观测。
技能库
所有技能的集合，学习线写入、消费线读取，两线共享。
结晶
把成功做法连同证据固化为技能的过程。
里程碑技能
多个技能组合成的复合技能，标记一个能力台阶。
维度
一道题被拆解出的考察点（如「按部门分组求均值」）。
裁判（Referee）
独立取数复核答案的角色，与出题、答题角色分离。
知识图谱
三层结构（维度→工具→表），记录指标语义与取数配方，是模型的「教材」。
control_primitives
原版 Voyager 塞进提示词的函数源码；本系统用知识图谱充当其等价物。
抓手（Grab）
场景中可用的取证手段（查询、读文件、搜仓库等），注册制，学习侧与消费侧同一份菜单。
掌握度
带半衰期的记忆账本：复用与无提示答对增强记忆，求助打折不加速遗忘。
半衰期
掌握度衰减的时间常数；只有「答对且没用提示」才拉长它。
场景（Scene）
隔离的基本单位：独立技能库、图谱、数据工作区（四种 kind，见 6.2）。
失败账本
判错题目的去向，反哺课程出题——从哪里跌倒，就从哪里再出题。
