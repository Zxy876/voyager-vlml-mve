摘要

问题：真正烧 token 的人，说不清钱烧在哪一步。一次生成类任务卡住，预算通常消耗在 决策、试错、重渲染三段上，但没有任何工具把这三段分开报账。换更强模型、加更多工具、写更长提示词， 都只能降低总消耗，不能告诉你哪一步本来不该花。

做法：MVE 不做事，只做测量。它把一道题拆成若干考察点，逐个尝试闭合； 闭合的那几条结晶成技能，备着下次直接用；没闭合的那几条如实留在原地。 它只用两个键（开始 / 停止）由人驱动，回答全部落在对话页，每一种回答都写明 「这次凭什么这么说、下一步该做什么」。

结果：新数据域一条命令接入、零代码改动、普通笔记本 20 分钟跑通完整闭环； 同一道题、同一数据源下维度集稳定（缓存键 md5(问题)+md5(数据源)）， 因此多次运行可直接对比。本机实测：文档型场景从「维度全指向空库、判未闭合」到 「维度框在文档上、2/2 用 read_file 闭合、status=learned」。

怎么算它有用：在 agent 上把同一任务跑到超支（未达成），再带着 MVE 给的配方复跑， 不超支且达成即优于前者。这条判定写在 第五章，含三个必须先钉死的前提。

本文是导读版：不要求读过 Voyager 论文或源码。行号级论证见 完整版白皮书， 以及随仓库发布的 docs/定位与验收-代码取证.md。

序言

这份白皮书的前一版，把自己的定位写成「端侧大模型能力成长框架」。那是个宣传品的写法： 它承诺能力，于是读者第一个问题必然是「那你有什么技能」。而 MVE 的对话页没有身份 ——它不注入任何系统提示词，也不假装自己是助手。所以那个问题它能答得很平庸，这是如实表现，不是缺陷。

把测试链接发给十几个人之后，出现了一个稳定的现象：几乎所有人都在对话框里问 「你有什么技能」「你觉得你的技能能被消费吗」。这不是他们的误解，是入口形态造成的 ——一个输入框，人自然当成 agent。而每次纠正这种误解，都在消耗别人对产品的第一分钟耐心。

所以这一版换了写法：不再声明能力，只声明测量。它是一台量具， 告诉你三件事：这题现在能不能答、这次的答案凭什么可信、以及以前是怎么跑通的。 量具不需要回答「你会干什么」，它只回答「测出来是多少」。

这个改动不是修辞。它决定了后面每一章的写法——讲输出要先讲怎么读， 讲使用要先讲两个键，讲价值要先讲怎么结算。

一、问题：token 花在哪一步，没人测量

先说清楚这不是「模型不够强」的问题，再看现有方案为什么都没解它。

1.1 一次典型的撞壁

一个真实场景：让 agent 做一张落地页/一段前端逻辑/一组图。第一次跑，它生成了，但不对； 改一版，还不对；到第七版，预算烧光了，人自己把需求改了，最后交出来的东西跟最初要的不是一回事。

事后回看，钱花在了三个地方：

段落典型消耗事后能不能说清
决策选哪个方案、根因在哪、参数取多少、必须放弃什么说不清——它混在各种尝试里
试错改了 7 版，每版都重跑一遍决策只知道"改了很多次"，不知道为什么改
渲染出像素、出帧、出文件反而最便宜——贵的是重来，而重来贵在重跑决策

所以真正的缺口不是「模型不够聪明」，而是没有任何东西把这三段分开报账。 人只能得出一个总量：这次花了这么多，没做成。

1.2 三种「看起来是解法」的方案

做法它解决什么它没解决什么
换更强 / 更贵的模型单次成功率降的是总量，不是「哪一步本来不该花」；下次换个任务，账还是糊的
加更多工具 / MCP能做的事更多工具越多，试错空间越大；不加测量，等于把可浪费的面扩大
写更长的提示词 / 工作流把经验前置成约束约束是人猜出来的，不来自实际成败；猜错了还要再叠一层

三条路都在降低消耗，没有一条在定位消耗。而只要定位不了， 下一次仍然只能靠感觉调。

1.3 测量需要什么

把「哪一步浪费」变成可读的数，只需要三个条件，都不复杂：

同一题能跑两次
+
变量可控（数据/工具/材料）
+
结果可比（同一套考察点）
→
差值才有意义

三个条件在通用 agent 里都难成立：会话一关，状态全丢；工具面每次都在变；同一句话问两次， 拆出来的子问题都可能不一样。这正是 MVE 存在的理由——它把这三件事做成结构： 场景隔离（变量可控）、维度缓存（结果可比）、技能库（上一次的经验不再丢）。

二、它是什么、不是什么

这一章是全篇的地基。定位错了，后面每个功能都会被读错。

2.1 不是 agent —— 这是设计，不是缺失

MVE 的对话页没有任何系统提示词，也不注入人格。它和面板里那条消费通路是同一个入口： 把问题交给同一套「检索已学技能 → 编排 → 兑现 → 核对」的流程。因此：

  • 问「你有什么技能」，它没有身份可以陈述，只能拿通用语料答——中规中矩正是如实表现；
  • 如果给它注入「你是具备技能的 agent」，它就开始演，而测量立刻被污染：你测到的将是它扮演的水平，不是它积累的水平。

这就是为什么这件事不该用 prompt 修。正确的纠正发生在第一屏： 让它一打开就像仪表盘，而不是聊天窗口（见 第四章）。

一句话区分
agent 的输出是答案；MVE 的输出是下一次交互的入口。 所以「你有什么技能」这个问题在 MVE 里是问错的——正确的是先问一句， 它会告诉你这题能不能答。它用回答暴露自己的能力边界，而不是用自我介绍声明能力。

2.2 是量具：四个可读的量

量回答什么问题它的局限
闭合率这道题拆出的考察点，这次真答到了几个单看会骗人——必须配纯度（见 7.4）
闭合纯度闭合的那几条，材料是不是真的（来源标记 + 引文可定位）取决于材料本身；材料错了，纯度也只是「错得一致」
抓手命中哪些工具一次直达，哪些方向空转（工具名序列可读）它告诉你"哪个抓手没用"，不告诉你"该造什么新抓手"
复用效果这次命中了几条技能、涨分来自哪次学习、命中却用不上的原因重放 ≠ 跑通，要看「命中却没用上」的原因字段

四样里，只有 token 不由 MVE 记。这是刻意的：钱花在 agent 侧， MVE 再记一本账，只会变成两本对不上。所以验收必须回到 agent 侧结算（第五章）。

2.3 为什么必须端侧

端侧在这里不是「隐私口号」，是测量的前置条件：

  • 数据不出域 —— 你要测的是自己那份库/文档，它不能先上传到别人那里；
  • 变量可控 —— 场景目录、技能库、图谱都在本地文件里，改一个变量就是改一个文件；
  • 可重跑 —— 学习要反复调模型，成本和网络依赖必须压到能承受。

框架本体刻意做轻：一个单文件 HTTP 服务 + 本地 duckdb 文件，无数据库服务、无消息队列、 无容器编排，一台普通笔记本即可运行。模型可插拔——学习闭环对模型只有「给文本、收结构化输出」 一个假设，端侧小模型或云端 API 都能接（当前验证使用 glm-4-flash）。

三、怎么读它的回答：输出就是交互

这一章是使用说明书。读完它，你应该能自己判断「这条回答能不能用、下一步该做什么」。

3.1 为什么不能写成字段字典

MVE 的输出不是一个答案，是答案 + 可信度 + 来源 + 计量。如果按字段罗列， 读者得到一张表却仍然不知道该干什么。而实际上，每一句口径本身就是下一句的指令：

  • 「未学」= 你该让它学一遍，然后原句再问；
  • 「不可达」= 你该补环境，换问法只会把「环境没接上」伪装成「这题本来能答」；
  • 「复用成功」= 你该追问这题的另一面，看它还接不接得住。

所以这一章按回合写，不按字段写。

3.2 七种回合

① 未学最常见 · 不是失败
⚠️ 未学：这道题还没学过，检索不到已学配方 —— 不编数。

它在说：这类题没有积累，拒绝编造。

你的下一句：让它学这一题；学完用原句再问一遍（换问法会换维度，等于换了一道题）。

它什么时候在骗你：材料本身缺失时，「学了也是学错」——它会一本正经地学出无关内容并结晶入库（真实事故见 7.4）。

② 库内取数最硬的一种
库内半场：已验证取数（可复现）；

它在说：数来自库内查询，判官独立复核过。

你的下一句：可以直接用。想复现，给同一份库即可。

它什么时候在骗你：2026-11-03 之前，联网缓存被写进库之后也这么标——口径被冒名。 现在必须同时看来源标记：只有材料确实来自库内，才算「库内」。

③ 上传文件取数2026-11-03 新增
上传文件半场：引文可定位（复现需同一份文件）；

它在说：技能里的引文，能在你上传的那份文件里逐字找到。

你的下一句：可以用，但清楚它的前提——换一份文件就失效。

它什么时候在骗你：只在来源标记为「上传」时成立。若技能是从网页学的，标成这句就是错的。

④ 联网 claim只当线索
外部半场：联网 claim（未验证、不入库、不计入学习曲线）

它在说：来自公开网页，没验证过。

你的下一句：当线索，别当结论；要它变成能力，得在有材料的环境里学一遍。

它什么时候在骗你：裸实体名必撞名。「心悦」实测撞上腾讯心悦会员、同名网络小说角色、 河北某高校新闻——三个都跟用户的文集无关。检索范围越大，撞名越致命。

⑤ 不可达别换问法
unreachable —— 环境缺东西（库 / 文件 / 工具），连模型都没调就拒绝

它在说：不是这题不会，是这题够不着。回答里会说明缺什么。

你的下一句：补环境（装数据源、开开关、传文件），然后原句再问。

它什么时候在骗你：遇到不可达就改问法是最常见的错误交互—— 把「环境没接上」伪装成「这题本来就能答」，你会在错误的地方反复烧 token。

⑥ 复用命中看解释，不看布尔
reused = true；涨分解释：这条技能来自哪次学习；命中却用不上的原因：……

它在说：这次命中了已学配方并重放。

你的下一句：追问这题的另一面（换个聚合口径/换个时间范围），看它还接不接得住—— 接得住才是真技能，接不住说明它只对原问法有效。

它什么时候在骗你：重放 ≠ 跑通。命中但用不上时，「命中却用不上的原因」字段非空， 而外层仍可能显示「复用成功」。

⑦ 学习结论六种状态

learned（已学成） / partial（部分闭合） / no_evidence（无证据） / unreachable（够不着） / prepared（已备料未执行） / failed（失败）

它在说：这一轮结束时的状态。只有 learned 会结晶出完整技能。

它什么时候在骗你：learned 只说明「维度闭合」，不说明材料正确—— 纯度要单独看。反过来 partial 不代表白跑：闭合的那几条已经结晶入库了。

3.3 三种「不行」的区别，决定你下一步做什么

你看到真正含义下一步
未学环境够得着，但没积累学一轮，原句再问
不可达环境够不着，学也没用补数据源 / 文件 / 工具开关
学到但答不对材料错了，或者维度拆偏了查这条技能的来源标记；补材料；必要时删缓存重学

把这三类混为一谈，就会产生最常见的浪费：在不该学的地方反复学，在不该重问的地方反复重问。

3.4 什么时候别信它

三个已知误报，写在这里而不是藏起来
① 「库内已验证」被联网缓存冒名（2026-11-03 前）——现在靠来源标记分辨。
② 裸实体名检索必撞名——实体名越短越危险；带场景上下文再检索才是正解。
③ 未计分不是 0 分——掌握度显示空值时，可能只是这轮没归题、没判分，别当 0 读。

四、怎么用它：两个键的循环

操作者不需要懂任何机制。两个键 + 一个输入框，就是全部操作面。

4.1 两个键

按键作用
▶ 启动学习开始一轮学习。主循环不带自动停，跑到你点停止或跑满上限
■ 停止任务边界优雅退出，不硬杀；已经学会的技能不会丢

没有难度选择、没有选题键钮——范围由知识图谱的缺口决定，哪里没覆盖就练哪里。 这是刻意的减法：操作面越小，测量越不容易被人手干扰。

4.2 一圈完整的循环

对话页原样输入需求
→
▶ 启动学习
→
看哪几条闭合
→
回对话页重问那几条
答上了 → 这题成为 r
或
答不上 → 改一点东西 → 再 ▶ 启动学习

循环终止条件只有一个：r = 对话能回答。

4.3 变异源：不改东西，重学就白跑

这是整套流程里唯一会失效的情形：材料、问法、数据源完全不变时重学， 大概率复现同一结果——两键按多少次都是原地打转。所以「想办法提高命中率」不是可选项， 它是这个循环的变异源。合法的改法有三种（都不动题面）：

  • 补上传材料（缺什么补什么）；
  • 修数据源（表名、列名、字段口径）；
  • 细化考察点（这会改问句 → 会重拆维度，等于换了基线，需要重新记录）。
要防的一种过拟合
把技能描述改成和测试问句同词，命中率能刷到 100%，但换个说法就掉。 判断方法：换一种表述还命中，才算数。

4.4 锚点：闭合的那几条

一次学习跑下来，N 条考察点里常常只有 1–2 条闭合。这 1–2 条就是锚点：

  1. 它们已经结晶成技能，可以直接被复用；
  2. 它们划出了这个任务在 MVE 下当前的能力范围——追着它们问、加深、验证，边际收益最高；
  3. 没闭合的那些不是失败记录，它们标出了「该交给 agent 的部分」。

所以「1/5 闭合」不是学习失败，是仪器测到了一次边界。把它当失败，就会去刷闭合率； 把它当测量结果，就会去问那 1 条。

4.5 r = 对话能回答

这个定义比闭合率、掌握度、任何日志字段都硬，理由很简单：它是使用者唯一看得见的东西。

而且它自带解释——答不上时，回答会说明是未学、不可达，还是材料缺，人不需要去翻日志。 日志是给开发者复盘的（哪一轮失败、试了哪些工具），不是给使用者做判定的。

五、怎么算它有用：token 对照结算

这一章要回答一个很具体的问题：凭什么说「用了 MVE 更好」。

5.1 指标换成 TPS，别用「省了百分之多少」

基线那次是烧完预算仍没解出来，有效产出是 0。它不存在「省了 40%」这种说法——它是从 ∞ 到有限：

TPS = 本次会话累计 token / 达成任务数

① 基线：触顶预算，达成 0  →  TPS = ∞
③ 复跑：≤ 预算，达成 1    →  TPS = 有限值

只要「达成且不超支」，TPS < ∞ 就恒成立。

这一点比常规 A/B 省事得多：不需要算百分比，不需要重复实验才敢下结论。

5.2 三个必须先钉死的前提

前提为什么怎么钉
同一条预算线线一移动，「不超支」就没有意义每次记录写明这条线的取值与来源
配方成本计入最容易作弊的地方：只报任务本体，不报配方注入，等于把成本挪进看不见的抽屉条形拆两段；红线：配方 token / 预算 > 20% 判这次迁移不划算
人的记忆隔离第一次超支后，人已经知道哪条路不通；第二次省下的可能是人的进步必须跑「干净会话组」才算强证据

5.3 三组对照

组配置能证明什么
① 基线直跑，无配方触顶预算未达成 → TPS = ∞
② 原人 + 配方踩过坑的人弱证据：省了，但可能省的是他自己的记忆
③ 干净会话 + 配方新会话、不知情，只有配方强证据：省了，说明配方是可交付的资产

只有 ③ 过，才算 MVE 的贡献。② 过而 ③ 不过，说明价值留在了人身上—— MVE 就退化成记事本，不是配方工厂。这也顺手定义了复用的产品形态： 配方必须脱离踩过坑的那个人也能用。

5.4 还有一笔账：摊销

单次净节省  Δ = 预算线 − (任务本体 + 配方注入)
回本次数    n* = 学习成本 L / Δ

单次不超支只是必要条件。n*=3 值得留；n*=50 只对高频任务有意义； Δ≈0 则「技能省 token」这一半价值是伪命题——那时 MVE 只剩「暴露缺陷」那一半， 而那本身也是产出，只是叙事要改。

5.5 什么时候这个对照不成立

  • 预算线在两次之间被调整（模型涨价、上下文变长、工具集变了）；
  • 配方注入的成本没有计入，或计入方式说不清；
  • 复跑用的是同一个会话（上下文里已经有上一轮的记忆）；
  • 任务本身在两次之间被改了（哪怕只改一句）；
  • 达成的判定由人主观给出，而不是由产物本身可验证。
MVE 在这一章里只需报一项
配方的 token 长度。运行 token 不由 MVE 记——它不产生那笔账单。 测量必须发生在被测量的地方。

六、R 的边界：生成类任务怎么进来

烧 token 最凶的人做的是生成类工作，而 MVE 不产出物。这一章解释为什么这仍然成立。

6.1 烧 token 的是决策，不是渲染

渲染本身很便宜，重渲染才贵——贵在每次重来都要重跑一遍决策。所以把决策抽走单独解决， 产物留给 agent，等价性成立：

生成任务 = 决策集 D × 渲染 f
MVE 交付 D        ← 一句话：参数 / 判据 / 根因
agent 执行 f(D)   ← 产物，预览也在这里

这就是「等价代换」的严格含义：MVE 交付的是 f 的参数，不是 f(x) 的结果。 既然不交付产物，「看不到预览」就不再是缺陷——因为本来就不该由它承担。

6.2 三条判据：什么能代换

判据说明
产物可抽离把产物拿掉后，问题仍成立吗？「帮我做个落地页」不成立（这是执行委托）；「这个落地页在 768px 下栅格取几列」成立
一句话说得完，且不含「看情况」一旦出现「看情况」，说明还没抽到决策层，只是把任务换了个说法
带回 agent 无需翻译如果要人再解释一遍，就没通过交付性检验

三条全过才代换。只要有一条不过，就如实拒绝——告诉对方「你缺的是执行，不是决策」。

6.3 四类任务的答案长什么样

类型一句话问法一句话答案的形态
代码<框架+版本> 下 <报错原文> 的根因是哪个？根因=X；触发条件=Y；代价=放弃 Z
前端 UI<组件> 在 <宽度区间> 下栅格、间距、断点取什么值？12 列 / gap 24 / 断点 768·1024 / 宽 1200
AIGC 画图要得到 <视觉特征>，prompt 必须含/必须排哪些词？必含：材质+光位+镜头；必排：plastic；权重<0.6 无效
视频<镜头意图> 在 <时长> 下走哪条路径更稳？首帧+末帧；单段≤3s；运镜前插 1.5s 静止

6.4 三类不可代换

  • 执行层能力不足（模型画不出那只手、渲染引擎不支持那个效果）——不是决策问题，学一百遍也没用；
  • 审美判定（「够不够好看」）——没有客观判据，一句话给不出；
  • 私有上下文缺失（内部组件库、品牌规范）——看不到，也不能编。

这三类应当触发「未学 / 不编数」。承认边界比扩大覆盖更能建立可信度。

6.5 「哪几条闭合」就是 R

不必预先判断哪些需求可以代换。人原样输入需求，跑一轮学习，N 条里闭合的那 1–2 条， 就是这个任务在 MVE 下换算出来的 R。原因在机制层面：

原样需求
→
拆成考察点（= 决策点）
→
逐点闭合判定
→
闭合的点结晶成技能

「维度闭合」与「决策集完整」在这里是同构的：一个「做个落地页」会被拆成 断点、间距阶梯、首屏必含、必须放弃什么——四点都有结论，配方就完整了。

顺带的收益比方案本身更大：配方里不再绑 SQL 与工具名单，只剩取值与条件—— 纯文本参数跨 agent 无损搬运，「跨工具面迁移会撞在调用层」这个风险随着 R 缩小自动消失。

代价要写在明面上
放弃预览不是免费的：判定延后——参数对不对只能在 agent 渲染后才知道， 交互从「对话内闭环」变成「跨工具闭环」。所以闭环必须靠回灌： MVE 给参数 → agent 渲染 → 人看 → 回报跑通/没跑通。回灌一断，配方会慢慢退化成「看起来很有道理的话」。

七、证据

所有关键声明都附可复现的实测；失败的实测也照登，包括仪器测到自己出错的那次。

7.1 知识图谱消融（同一道题，第 1 轮，不求助）

条件覆盖率表现
无图谱0% wrong连败 SQL 列都取错
图谱仅作提示20% partial骨架对，过滤位置错
图谱 + 结构/参数硬断言100% correct连败值与起点全部正确

一条重要教训：提示打不过模型的强先验，约束才行。

7.2 插拔与学习闭环实测（2026-11-01，一台普通 Mac）

实测记录（全程无需云服务器）
① 运行时插入新场景（自建员工/部门/工资库）：一条命令、代码零改动，面板场景数 1→2，既有场景无污染；
② 在该场景发起学习：status = learned，3/3 个考察维度闭合，4 条技能结晶入库；
③ 消费侧导入同一问题：reused = true，命中刚学的复合技能，掌握度 0 → 1/30，面板曲线出现数据点。

7.3 文档型场景：修复前后对比（2026-11-03，本机）

同一道题：「上传的文档里，桃子的手刹变成了什么？」——空库 + 一份 txt。

条件拆出的考察点指向结果
修复前（场景 U / V）全部指向 scene.duckdb（空库）只敢读索引文件；判未闭合
修复后（场景 W）直接框在 uploads/…测试文集.txt 上2/2 用 read_file 闭合，status=learned，结晶 2/2

根因不是「没做」，是「做了没接上」：读文件的原语早就存在（带沙箱守卫，只能读本场景目录、拒密钥文件）， 但场景型环境的目录变量恒为空串，导致它从未被注册进执行环境。一行兜底 + 清单注入即可。

7.4 反例：闭合率 100%，纯度 0（2026-11-03，场景 J）

仪器测到自己出错的那一次
用户上传 3 万字文集后提问。学习侧结晶 4 条技能，闭合率 100%。
但库里只有两张联网缓存表，文集从未进入取证路径；闭合的内容是腾讯「心悦会员」游戏 VIP、 同名网络小说角色、河北某高校新闻。
结论：闭合率 100%，纯度 0。这批技能随后被反复「复用成功」，复用的是错误来源。

这次事故带来了三处改动：来源标记（库内/上传/联网）、引文字面守卫（技能引文必须能在原文里逐字定位）、 上传清单注入执行上下文。更重要的是它改了这一版白皮书的写法： 从今往后，闭合率不配纯度，不许单独引用。

7.5 能力边界是架构强制的

系统会响亮地说「不」
向一个不含相关表的场景提问 → unreachable，在触达任何模型调用之前被可达性检查拒绝。 能力边界不靠提示词自觉，靠架构拒绝。

八、能力边界与诚实声明

一份说明书的可信度，取决于它写清楚了自己的误差范围。

8.1 测量本身的边界

边界含义与影响
token 不由 MVE 记验收必须回 agent 侧结算；MVE 只报配方长度。想让它自己报「省了多少」，做不到
闭合率必须配纯度单看闭合率会被优化成「更容易闭合」（刷分）；纯度取决于来源标记与材料本身
只测「能不能答」不测「答得好不好看」；审美类判定不在能力范围内
不产生产物不渲染、不预览；判定延后到 agent 侧，靠回灌闭环
掌握度挂在题上是「带半衰期的记忆账本」，不是按能力项归档的评估体系
技能绑死出处的题配方里写死具体标识符，换数据域要重学
旧维度缓存不重拆骨架按「问题+数据源」缓存；换了材料口径要用新口径学，需先删该场景缓存
文档型场景的复合技能不入库里程碑复合技能要求组合产物是 SQL 形态；文档场景暂不满足
图谱未消费全部底层表表节点仅从种子题 rubric 的 SQL 派生
部分派生数据层未随开源发布若干派生表在公开源为 0 行，原料表在公开源中

8.2 两条已被证伪的自我描述

  • 「它是一个具备技能的 agent 框架」——对话页没有身份，它不会也不想假装；把它当 agent 用会持续失望；
  • 「它能告诉你省了多少 token」——它不记运行 token，只能告诉你配方有多长、这次有没有复用、复用来自哪次学习。

把这两条写在白皮书里，比藏起来更有用：使用者少走一次弯路，产品少一个错误的期待。

九、如何复现与参与

一台普通电脑（无需 GPU / 集群）+ 一个大模型 API key，30 分钟内可跑通第七章的全部实测。

9.1 本机复现（约 30 分钟）

# 1. 克隆仓库并准备环境（python ≥ 3.10）
git clone https://github.com/Zxy876/voyager-vlml-mve.git
cd voyager-vlml-mve
python3 -m venv .venv && source .venv/bin/activate
pip install duckdb httpx pypdf gymnasium

# 2. 配置大模型 API（任选一家，默认智谱 glm-4-flash）
cp .env.example mve/.env    # 填入你的 ZHIPU_API_KEY

# 3. 启动面板（单文件 HTTP 服务，无其他依赖）
MVE_PANEL_PORT=8877 python mve/dashboard.py
# 浏览器打开 http://127.0.0.1:8877/mve/

# 4. 跑全量单测（可选，验证环境完整）
python mve/test_*.py

之后新建一个场景（指向你自己的 duckdb/CSV，或直接上传一份文档）， 在对话页原样输入你的需求 → 点「▶ 启动学习」→ 回对话页重问闭合的那几条。 模型可插拔：把 BASE_URL/MODEL 指向任意兼容接口（含本地部署的端侧模型）即可切换。

9.2 适合谁、怎么参与

如果你是……建议的切入点
被 token 账单困扰的重度使用者拿你自己撞过壁的任务跑一遍，按第五章结算，把结果告诉我们——不成立也是结论
Agent 开发者看第七章 7.4 那次事故：你的 agent 有没有把「看起来成功」当成成功；再对照 7.5 的架构拒绝
LLM / Agent 研究者读完整版「与原版 Voyager 同构对照」，每条改动都给 file:line，可直接引用或挑战
数据 / 后端工程师把你手头的数据库接成新场景，验证 1→n 契约的边界（哪些数据域插不进去，对我们最有价值）

本项目的开发纪律是「文档声明与产品能力一致」：复现时若发现任何一条声明对不上实测， 请提 Issue——预期差本身是我们最重要的一等公民。

十、术语表与深入阅读

10.1 术语表

场景（Scene）
隔离的基本单位：独立技能库、图谱、数据工作区。变量可控靠它。
考察点（维度）
一道题被拆出的考察点（如「按部门分组求均值」，或生成类任务里的一个决策点）。
闭合 / 未闭合
这一轮是否答到了该考察点。闭合的才结晶；未闭合的如实留下。
闭合率
闭合的考察点数 ÷ 总考察点数。回答「R 有多宽」。
纯度
闭合的那几条里，材料来源正确且引文可定位的比例。回答「R 有多真」。与闭合率必须并报。
技能（配方）
一次被验证成功的做法，附带当时的真实观测，可检索、可复用。
结晶
把闭合的做法连同证据固化为技能的过程。
来源标记
技能材料来自哪一面：库内 / 上传 / 联网。它决定这条配方可不可搬、能不能复现。
抓手（Grab）
场景中可用的取证手段（查库、读文件、联网、搜仓库）。注册制，学习与消费同一份菜单。
掌握度
带半衰期的记忆账本：复用与无提示答对增强记忆，求助打折不加速遗忘。
未学 / 不可达
两种「答不上」，处置完全不同：前者去学一轮，后者去补环境。
r
本任务在 MVE 下当前能交付的范围，判定标准是对话能回答。
验收（TPS）
每个达成任务消耗的 token。基线触顶未达成 → ∞；复跑不超支且达成 → 严格优于。
