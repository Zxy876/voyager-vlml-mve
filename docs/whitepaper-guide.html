摘要

问题：大语言模型擅长「说」怎么做，但无法证明自己「做到过」。在真实数据库场景里， 它会幻觉出不存在的表名和数值，且每次回答都从零开始，问一百次不会比第一次更好。

方案：本项目把 Voyager 的在线学习范式从游戏世界迁移到数据库世界——不重新训练模型， 而是让模型像学生一样刷题：出题、动手查库取证、被判卷、把做对的做法沉淀为技能；人提问时检索技能 编排作答，复用情况逐笔记账。三道闸门保证「进技能库的每一条都附带真实证据」。

结果：知识图谱消融实验覆盖率 0% → 100%；新数据域一条命令接入、零代码改动、20 分钟 跑通完整学习闭环。系统全部开源，第五章给出本机复现路径。

本文是导读版：不要求读过 Voyager 论文或源码。行号级技术论证见 完整版白皮书。

序言

2023 年，NVIDIA 的 Voyager 项目展示了一种令人印象深刻的能力：一个 LLM Agent 在游戏 Minecraft 里自主设定课程、执行任务、把成功经验写成技能存进代码库，能力随游玩时间单调增长。 它不需要重新训练模型——模型权重不变，变的是模型身边那份自己挣来的技能库。

这引出一个自然的问题：这套范式离开游戏还成立吗？游戏世界给了 Voyager 三样奢侈的 东西：即时得分（系统知道任务成没成功）、可读的实现（技能就是源码，塞回提示词就能复用）、 封闭世界（表名、物品、方块是有限的集合）。

真实的数据世界一样都没有：没有标准答案、没有源码可看、表和字段开放且会变。本项目 （Voyager-VLML-MVE）就是对这三个缺失的一一回应。这份白皮书讲清楚：问题是什么、现有方案 缺什么、我们怎么解、证据在哪、以及你如何在自己电脑上复现它。

一、问题：为什么 LLM 在真实数据世界「越用越弱」

先定义问题，再看现有方案为什么没解掉，最后说明可迁移的思想资产是什么。

1.1 直接问大模型的四种失败

失败模式具体表现
幻觉编造不存在的表名、列名，甚至编出貌似合理的数值——且语气与真话无异
无积累每次对话从零开始：第 100 次回答同样的查询，不会比第 1 次更快更好
知其 tool 不知其值知道该「查询数据库」，不知道这个指标在哪张表哪个字段，只能猜
不可核查回答无法追溯到「当时真实取到了什么数」，对了不知道为什么对，错了无法归因

1.2 现有方案的不足

路线做法在数据场景的短板
微调 / RLHF把领域能力训进模型权重每换一个数据域都要重新训练；成本高、周期长，能力更新滞后于数据变化
RAG检索文档片段拼进上下文给的是「知识」不是「能力」：模型读到了 schema 文档，仍可能写出跑不通的查询，且没有对错反馈
纯 Agent 循环ReAct 式边想边做每轮的试错经验随会话丢弃——失败过的坑下一个问题接着踩
Text-to-SQL 微调在 (问题, SQL) 对上训练强依赖标注对；对 schema 演进和数据域切换脆弱，同样缺少在线改进回路

共同缺口：都缺一个「从自己的成败中积累可复用经验」的在线闭环。

1.3 Voyager 的启示与迁移障碍

Voyager 证明了在线闭环可行，但它的三个前提在数据世界全部失效：

游戏世界的奢侈前提数据世界的现实
即时得分：游戏API直接报成功/失败查询跑通了 ≠ 取到了对的数 ≠ 回答了问题
技能即源码：成功代码直接塞回提示词复用没有「源码」可看；要复用的是取数路径，不是代码文本
封闭世界：物品与方块有限可枚举表、字段、指标开放且随业务演进

所以问题可以精确表述为：把 Voyager 的「课程—执行—判卷—固化」闭环搬到数据世界， 需要重建哪几块地基？这正是第二章的内容。

二、解决方案：Voyager-VLML-MVE

三个缺失 → 三块地基：判卷地基（双线+判据分层）、教材地基（知识图谱）、信任地基（三闸）。

2.1 总体思路

不训练模型，而是给模型两样外挂：

  • 一份技能库：每条技能 = 一次被验证成功的取数做法 + 当时的真实观测。模型做对过一次，就永远会做第二次；
  • 一张知识图谱：记录「什么指标、从哪张表哪个字段、用什么路径取」——回答「值从哪来」的教材。

系统的全部设计纪律归结为一句话：凡是被机器复用的东西，必须附带真实证据。

2.2 双线架构：练习线和考试线分开

学习线：出题 → 检索 → 动手执行 → 判卷 → 固化技能
判据：success 布尔 —— 真实取到数才算成功
消费线：人提问 → 检索技能 → 编排 → 叙述 → 裁判复核
判据：裁判独立复核 —— 作为交付尺度

两条线共享同一份技能库与知识图谱，但判据语义不同。关键纪律：消费只编排复用，不现做 合成——回答人的问题时组合已验证的技能，不临场发明。这让每条回答都能追溯到「当初哪次 练习验证过它」。

2.3 知识图谱：给模型一本「看不见的教材」

原版 Voyager 复用技能靠把函数源码塞进提示词。数据世界没有源码可看，本系统用一张 三层图谱（维度 → 工具 → 表）替代：记录每个指标的语义、取数配方、各表字段与典型错误。 模型写查询前先翻书，而不是靠先验猜表名。

效果：同一道题，三种条件（第 1 轮、不求助）
无图谱 → 覆盖率 0%（连列都取错）；图谱仅作提示 → 20% partial（骨架对但过滤位置错）； 图谱 + 结构/参数硬断言 → 100%。一条重要教训：提示打不过模型的强先验，约束才行。

2.4 防幻觉三闸：进库的每一条都附带真实证据

闸拦什么怎么拦
闸一：防膨胀技能库被低质配方刷屏入库三分支（added / rewritten / skipped）；少于 12 字或与已有技能相似度 ≥0.90 丢弃；检索每次最多 5 条
闸二：回灌闸技能描述与真实执行脱节判卷后的真实观测回灌进技能内容；解析失败重试，不靠想象补全
闸三：事实溯源结论里的数值、表名是编的叙述中的字面量必须全部能在真实取数结果中指认，指认不出就不许说

判卷采用「LLM 判 + 确定性否决」：全程没调过数据源 → 直接判负（真空防线）；执行层报错 → 直接判负；LLM 只在硬否决通过后裁决。判错不写技能库——错误做法不进库，因此不会经 复用链传播。

2.5 掌握度与求助：像老师一样记账

学生卡住可以求助，但只讲思路、绝不报数值——给数值等于泄题。求助记录在案：

情形记账结果
答对，且没用提示半衰期拉长（记忆更牢）
答对，但用了提示得分打 0.85 折，半衰期不动——不计全功，也不惩罚
答错进失败账本，反哺出题——从哪里跌倒就从哪里再出题
消费侧复用技能掌握度累计，重复提问可见增长

2.6 场景系统：1→n 可插拔

每个场景（数据域）有独立的技能库、图谱与数据工作区，非默认场景不继承默认库——这条 隔离契约来自真实教训：曾有查询跨库取到了另一个数据域的数据。四种场景类型覆盖从「绑定数据 库」到「数据源就是本机」的常见形态；插入新场景不重启、不清库、不改代码（实测见第四章）。

三、系统如何工作

两次「旅程」讲清机制。对照阅读：每个环节在完整版里都有 file:line 级论证。

3.1 一次学习的旅程（六阶段闭环）

① 课程出题
→
② 技能检索
→
③ Rollout 执行
→
④ 判卷
→
⑤ 结晶
→
⑥ 里程碑

① 出题：课程规划器依据图谱缺口出题，哪里没覆盖练哪里；② 检索：召回相关技能 作参考（≤5 条）；③ 执行：生成查询并真实执行，逐条记录工具调用与返回；④ 判卷： 判据分层裁决，失败进失败账本；⑤ 结晶：成功做法连同真实观测固化为技能（过三闸）； ⑥ 里程碑：多个技能组合成复合技能，标记能力台阶。

3.2 一次提问的旅程（消费线）

人提问
→
检索技能
→
多配方编排
→
叙述聚合
→
裁判复核
→
掌握度 +1

回答完成后由裁判独立取数复核（与出题、答题角色分离，避免自评）。回答明确标注复用了 哪条技能、来自哪次学习。

4.2 插拔与学习闭环实测（2026-11-01，一台普通 Mac）

实测记录（全程无需云服务器）
① 运行时插入新场景（自建员工/部门/工资库）：一条命令、代码零改动，面板场景数 1→2，既有场景无污染；
② 在该场景发起学习：status = learned，3/3 个考察维度闭合，4 条技能结晶入库；
③ 消费侧导入同一问题：reused = True，命中刚学的复合技能，掌握度 0 → 1/30，面板曲线出现数据点。

4.3 能力边界是架构强制的

系统会响亮地说「不」
向一个不含相关表的场景提问 → unreachable，在触达任何模型调用之前被可达性检查拒绝。 能力边界不靠提示词自觉，靠架构拒绝。

五、如何复现与参与

一台普通电脑 + 一个大模型 API key，30 分钟内可跑通本白皮书第四章的全部实测。

5.1 本机复现（约 30 分钟）

# 1. 克隆仓库并准备环境（python ≥ 3.10）
git clone https://github.com/Zxy876/voyager-vlml-mve.git
cd voyager-vlml-mve
python3 -m venv .venv && source .venv/bin/activate
pip install duckdb httpx pypdf gymnasium

# 2. 配置大模型 API（任选一家，默认智谱 glm-4-flash）
cp .env.example mve/.env    # 填入你的 ZHIPU_API_KEY

# 3. 启动面板（单文件 HTTP 服务，无其他依赖）
MVE_PANEL_PORT=8877 python mve/dashboard.py
# 浏览器打开 http://127.0.0.1:8877/mve/

# 4. 跑全量单测（可选，验证环境完整）
python mve/test_*.py

之后在面板里新建一个场景（指向你自己的 duckdb/CSV 数据），或在命令行里对任意场景发起学习， 即可复现「学习 → 结晶 → 复用 → 掌握度上升」的完整闭环。

六、能力边界与诚实声明

一份白皮书的可信度，取决于它说清楚了自己做不到什么。

边界含义
掌握度挂在题（topic_id）上是「带半衰期的记忆账本」，不是按能力项归档的评估体系
技能绑死出处的题，不迁移配方里写死了具体标识符，换个数据域要重学
消费判分是软尺子主尺子是「两边做法比对」（LLM 判），不是题库既有 rubric
图谱未消费全部底层表表节点仅从种子题 rubric SQL 派生
部分派生数据层未随开源发布若干派生表在公开源为 0 行，原料表在公开源中
个别报告类任务在公开源必然失败其实现写死查询 0 行的派生表

七、术语表与深入阅读

7.1 术语表

技能（Skill / 配方）
一次被验证成功的做法，存成可检索、可复用的条目，附带当时的真实观测。
技能库
所有技能的集合，学习线写入、消费线读取，两线共享。
结晶
把成功做法连同证据固化为技能的过程。
里程碑技能
多个技能组合成的复合技能，标记一个能力台阶。
维度
一道题被拆解出的考察点（如「按部门分组求均值」）。
裁判（Referee）
独立取数复核答案的角色，与出题、答题角色分离。
知识图谱
三层结构（维度→工具→表），记录指标语义与取数配方，是模型的「教材」。
control_primitives
原版 Voyager 塞进提示词的函数源码；本系统用知识图谱充当其等价物。
抓手（Grab）
场景中可用的取证手段（查询、读文件、搜仓库等），注册制，学习侧与消费侧同一份菜单。
掌握度
带半衰期的记忆账本：复用与无提示答对增强记忆，求助打折不加速遗忘。
半衰期
掌握度衰减的时间常数；只有「答对且没用提示」才拉长它。
场景（Scene）
隔离的基本单位：独立技能库、图谱、数据工作区。
失败账本
判错题目的去向，反哺课程出题——从哪里跌倒，就从哪里再出题。
