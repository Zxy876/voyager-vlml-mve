## 一、定位：它不是 agent，是量具

### 1.1 对话页没有身份，这是设计而不是缺失

| 主张 | 证据 |
|---|---|
| 对话入口全程没有 system prompt / 人格注入 | 全仓检索 `role: system`、`SYSTEM_PROMPT`、`系统提示` 于 `mve/dashboard.py` / `voyager_vlml/consume.py` / `mve/coach.py` → **零命中** |
| 对话页与面板走**同一条**消费通路 | `mve/dashboard.py:3560-3574`：`asyncio.run(_consume.consume(q, topic_hint=...))`，注释写明「与面板 /api/coach 同一条消费通路」 |
| 所以问「你有什么技能」答不好是**如实表现** | 无身份可陈述 → 只能拿通用语料答。若注入「你是具备技能的 agent」，它就开演，测量被污染 |

**结论**：别人误认为它是 agent，是**入口形态**带来的（一个输入框），不是能力描述带来的。
纠正方式不是加 prompt，而是让第一屏显示实测值（见第五节）。

### 1.2 它能测的四样东西，各自落在哪

| 要测的 | 数据在哪 | 代码位置 |
|---|---|---|
| **闭合率**（这道题有几个考察点真的答到了） | `maieutic_gate.check()` 返回 `addressed` / `open` | `mve/maieutic_gate.py:172-197`；`passed` 严格等价于 `open == []`（`:76`） |
| **闭合纯度**（闭合的那几条是不是真材料） | 技能条目 `provenance`（db/upload/web）+ 字面量守卫、引文守卫 | `mve/skill_store.py:321,426,446`；守卫在 `voyager_vlml/consume.py` 与 `mve/learn_orchestrate.py` |
| **抓手命中**（用哪个工具直达、哪个方向空转） | `coach_log.trajectory`（工具名序列）、`run_log.jsonl` 的 `verdict` / `errors` / `no_tool_calls` | `voyager_vlml/consume.py` 落 `coach_log`；`mve/learn_orchestrate.py:2296-2336` 落 `run_log` |
| **复用效果**（技能是否接得住、涨分从哪来） | `reused` / `used_skills` / `reuse_explain` / `reuse_errors`；掌握度 1/30 步长、半衰期 60 天 / 3 会话、用提示 ×0.85 | `voyager_vlml/consume.py:1464+`；`mve/mastery_model.py:60,70,77` |

**唯一不在 MVE 记的是 token**：全仓检索 `prompt_tokens` / `total_tokens` 于 `voyager_vlml/consume.py` → **零命中**。
这是 2026-11-03 的拍板（台账 #12）：钱花在 agent 侧，MVE 再记一本账只会两本对不上。
**验收必须回到 agent 侧结算**（见第五节）。

### 1.3 「抓手开和不开由学习策略决定」

- 动作注册契约 `ActionSpec`：五类来源（builtin / learned / plugin / mcp / local），`mve/actions.py`
- 学习侧与消费侧共用同一份工具菜单：`mve/learn_orchestrate.py:238-244`
- 2026-11-03 修复：`kind=scene` 场景此前 `local_dir` 恒为空串，`register_local` 不调用 → `read_file`/`list_files` 原语**存在但从未注册**；`scene_profile.py` 的 `kind=scene` 分支也不给 `scene_dir`（服务器实测 `profile('J')['scene_dir'] is None`）。已修，PR #3

## 二、输出就是交互（回合图鉴的代码出处）

用户的原话：「他的输出就是交互」。这在代码里成立——每条回答都带着**下一步能做什么**。

| 回合 | 代码原文 | 位置 |
|---|---|---|
| **未学** | `⚠️ 未学：这道题还没学过，检索不到已学配方 —— 不编数。` | `voyager_vlml/consume.py:2075` |
| **库内半场** | `库内半场：已验证取数（可复现）；` | `voyager_vlml/consume.py:2187` |
| **上传文件半场** | `上传文件半场：引文可定位（复现需同一份文件）；` | `voyager_vlml/consume.py:2185` |
| **外部半场** | `外部半场：联网 claim（未验证、不入库、不计入学习曲线）` | `voyager_vlml/consume.py:948,2191` |
| **不可达** | 场景 `kind=missing` → `status=unreachable` + `why` 说明缺什么，在触达模型前拒绝 | `mve/learn_orchestrate.py:760,892,945` |
| **复用** | `reused` / `used_skills` / `reuse_explain` / `reuse_errors` | `voyager_vlml/consume.py:1464+` |
| **学习结论** | `learned→ok` / `partial→partial` / `no_data→no_evidence` / `unreachable` / `prepared` / `failed` | `mve/learn_orchestrate.py:2314-2316` |
| **重问结论** | `verdict: "ok" if ok else "still_failed"` | `mve/revisit.py:224` |

**这就是为什么它能回答「输出字典」却不能回答「你有什么技能」**：
agent 的输出是答案，MVE 的输出是**下一次交互的入口**。

## 三、两键循环：操作者只有两个动作

| 判断 | 证据 |
|---|---|
| 「▶ 启动学习」按钮存在，运行中置灰 | `mve/dashboard.py:1486`：`${running?'disabled':''}` |
| 「■ 停止」按钮**存在**，未运行时置灰 | `mve/dashboard.py:1487`：`${running?'':'disabled'}`；另有驾驶舱版 `:556`、考试版 `:810` |
| 停止是**任务边界优雅退出**，不硬杀，已学技能不丢 | `mve/dashboard.py:1470,1504`：注释「停止 = 任务边界优雅退出（不硬杀，技能已落盘）」 |
| 主循环不带自动停：`while True`，只有点停止或跑满上限才退 | `mve/dashboard.py:537,565,740`，同构原版 Voyager `voyager.py:326` |

> ⚠️ **纠正（我此前的错误）**：22:05 那一轮我据 `grep '停止学习'` 无命中，判「面板没有停止键」。
> 实际按钮文案是「■ 停止」，`id=voyStop`。**两个键本来就都在**，这条不构成缺口。

### 3.1 多轮为什么可比：维度集不漂移

- 骨架缓存键 = `md5(question)` + `md5(db_path)`：`mve/maieutic_scaffold.py:170-184`
- 同一问句、同一数据源 → 复用**同一套维度** → 多轮观测是同一坐标系叠加，不是每次重新拆题

### 3.2 循环的变异源必须是「改一点东西」

材料、问法、数据源全不变时重学，大概率复现同一结果 → 原地打转。
合法干预：补上传材料 / 修数据源表列 / 调技能描述（改描述会改检索命中，可能改问句 → 重拆维度，需重设基线）。
要防的过拟合：**把技能描述改成和测试问句同词**，命中率刷到 100%，换个说法就掉。

### 3.3 r 的定义

`r = 对话能回答`。这是操作者唯一看得见的判定，且自带解释（答不上时回答会说明是未学 / 不可达 / 材料缺）。
它比闭合率、mastery、`covered` 都硬——**因为它是使用者唯一的验收信号**。

> ⚠️ **纠正（我此前的错误）**：我曾把「`run_log.covered` 恒为空」当成产品缺口。
> 事实成立（`mve/learn_orchestrate.py:2330` 附近 `"covered": []`、`revisit.py:231`、`voyager_vlml/loop.py:579` 三处均为空数组），
> **但对象错了**：判定发生在对话层，不在日志层。日志是给开发者复盘的，不是给使用者判定的。

## 四、验收：它有没有用，在 agent 侧结算

详见 `docs/验收协议-token对照.md`。要点与代码/事实的对应：

| 要点 | 依据 |
|---|---|
| 基线是「烧完预算仍未达成」，有效产出 0 → TPS = ∞ | 基线定义，非代码 |
| 复跑「≤ 预算且达成」→ TPS 有限 → 严格优于基线 | 同上，不需要大样本 |
| 配方注入的 token 必须计入 | 否则成本被挪进看不见的抽屉 |
| 人的记忆必须隔离（干净会话组才算强证据） | 「要么人进步，要么模型进步」——原人复跑省下的可能是人的记忆 |
| 配方必须能整段搬走：`code` + 工具依赖 + 口径 | 技能条目结构 `mve/skill_store.py`；`provenance` 是搬运可行性判据 |
| MVE 侧只需报一项 | **配方 token 长度**（运行 token 不记，已拍板台账 #12） |

**跨工具面迁移的现实风险**（必须在白皮书里写明）：
MVE 技能带 `sql` 与工具名（`coach_log.trajectory` 里那些），agent 侧工具面不一定同构。
`provenance` 可当预判：web 来源多为文本 claim，可搬；`query_sql` 来源要看 agent 有无等价工具。

## 五、R 的边界：生成类任务怎么进对话页

详见 `docs/代换表-生成类任务.md`。代码侧无需改动，理由是：

- `maieutic` 拆的「维度」与「决策点」同构：维度闭合判定 = 决策集是否完整（`mve/maieutic_gate.py`）
- 结晶只收闭合维度（`mve/learn_orchestrate.py` 两条写入通道：维度技能 + 里程碑组合技能）
- 因此「N 条里闭合的那 1-2 条」**就是**这个任务在 MVE 下换算出来的 R，不需要新增任何机制

**已知边界（本机实测）**：里程碑**复合**技能要求组合产物是 `SELECT/WITH`（SQL 形态），文档型场景的组合还不入库。

## 六、闭合率必须配纯度：场景 J 是现成反例

2026-11-03 场景 J（心悦文集）实测：

- 学习侧结晶 4 条 `learn_99e1f26e::*` 技能，**4/4 维度闭合**（闭合率 100%）
- 但 `scene.duckdb` 里只有 `web_docs(5)` / `web_facts(2)` 两张**联网缓存表**，文集 3 万字只在 `uploads/` 未入库
- 闭合的内容是：腾讯「心悦会员」游戏 VIP、同名网络小说角色、河北某高校新闻——**全部与文集无关**
- 结论：**闭合率 100%，纯度 0**。只盯闭合率，系统会被优化成「更容易闭合」（刷分，不是学习）

这也是 11-03 加 `provenance` 与引文字面守卫的直接动因。
